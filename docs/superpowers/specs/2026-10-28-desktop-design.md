# 电视开机广告开关：桌面工具设计

## 目标与使用者

面向普通小米 / REDMI 电视用户，提供中文 macOS 和 Windows 桌面工具：在同一局域网中发现或手动填写电视，按屏幕提示完成电视端调试授权，再检测型号、固件和广告开关，以一个操作关闭经过验证的开机广告路径，并在需要时恢复原状态。源码和可下载构建发布到 GitHub。

## 方案

比较了 Codex 插件、电视端应用和电脑桌面工具。桌面工具可以让未安装 Codex 的用户使用，也避免在电视安装额外应用；用户已选择 macOS 与 Windows。后端使用 Python 和官方 ADB；界面使用本地 WebKit / WebView2 桌面窗口，以提供标准可访问的表单与键盘语义。发布包包含运行所需的 ADB 及其许可说明，用户无需自行安装 Python 或 ADB；Windows 需要系统 WebView2 运行时。首次连接仍需要用户打开电视端 ADB 调试，并允许电脑授权。

## 界面与流程

根据用户后续要求重构：以连接电视、检测结果和关闭开关三个连续状态呈现，优先突出当前唯一主要动作；移除标语、常驻教学段落和重复标签。保留可访问的表单标签、键盘焦点、状态与错误信息；连接步骤放在可键盘操作的信息按钮中。仅在存在本工具创建的有效备份时显示恢复操作。用户更改目标 IP 后，必须重新连接，禁止旧连接继续写入。

## 行为与安全边界

- 设备发现仅查询局域网公开的投屏设备描述；允许手动填写局域网 IPv4，多个电视由用户明确选择。
- 每次连接后读取系统型号、设备代号、Android 版本、固件和原机桌面版本。只有全部匹配有证据的配置时才开放修改；其他设备只读检测，并展示厂家支持入口。
- 首个本机实测配置：`MiTV-MFTR0`、`freeguy`、Android 14、`OS3.0.107.0.UFTMATV`、原机桌面 `4.8.413`。只将 `system boot_ad_switch` 设为 `0`；读取原值、先保存本地恢复记录、写后读回。若原值已为 `0`，只报告已关闭。
- 首版另纳入有实际开关与开机观察记录的三个社区配置：`MiTV-ANTL0/starwars`（Android 5.1.1、固件 23.2.4.2225、桌面 3.38.1017）、`MiTV-MFTP0/alita`（Android 9、固件 23.2.10.6129、桌面 3.49.1601）、`MiTV-MTTP0/hugo`（Android 9、构建 21.4.9.2585 / incremental 2585、桌面 3.50.1621）。最后一项的报告只确认一次关开机，未证实完整重启。逐项记录来源和证据等级；不得宣传为本机实测，也不得按型号大类猜测适配。
- 恢复只使用本机先前保存的原值，核对同一设备身份与配置；原来不存在则删除新增键，原值为 `1` 则恢复 `1`。遇到无法可靠识别设备、未支持固件、意外原值、备份失败、写入或读回失败时停止并说明。
- 不安装电视应用、停用或卸载系统包、替换桌面、修改路由器、主动重启电视或收集/上传设备信息。提供清晰的电视重启验证提示；处理后建议关闭电视调试。
- ADB 使用单独本地服务，不打断系统其他 ADB 会话；命令绑定到授权连接的 transport ID，修改前再次核对连接时的设备身份和固件。官方 ADB 使用电脑用户目录中已有的默认调试密钥，缺失时自行创建。网络与子进程均有超时。设备唯一标识仅加盐哈希后用于本机恢复匹配，不写入公开仓库或遥测。

## 验收

- 对授权、发现、精确匹配、未知固件拒绝、初始值、重复执行、故障、设备切换和恢复进行自动测试。
- 在 macOS 上检查界面与完整模拟流程；Windows 在 GitHub Actions 上运行测试并构建 Windows 程序。发布 macOS Apple Silicon / Intel 与 Windows 包，检查运行时和第三方许可；未能实机验证的平台明确标注。
- 开源仓库包含普通用户说明、设备兼容表及来源、恢复方法、贡献方式、许可证；不得包含实际家庭网络地址、电视序列号、账户、设备密钥或专有电视 APK。
- 发布前检查仓库内容与构建结果；不能声称适配所有型号、永久去除所有广告，或将开机动画与商业广告混为一谈。
